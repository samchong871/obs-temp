Instance Groups
- Groups of VMs for same function
- GCP-based load-balancing
	- In addition to Blaise-based load-balancing
	- May cause conflicts

IAM
- Set permissions for user/account access
- Can allocate role (come with set of permissions) to account
- As dev, we have social-survey-prod role with owner access
- Application accounts, like nifi, have specific roles with the permissions required for that application's function
	- Should have least privilege access
	- Not perfect, but OK

App Engine
- Platform as a Service
- Write code for service
- Give code to App Engine to run
	- Don't need to create a container, etc.
	- Info about platform needed and it creates and appropriate container and runs
- All UIs (end "-ui") are in App Engine
- Endpoints also in App Engine (don't have "-ui" at end), e.g.
	- bts, bert
- Default language can be set
- Repos contain `<repo>/appengine_template/app.yaml.tpl` template file
- GCP Artifact Registry contains the actual containers
	- Can see info like vulnerabilities

Cloud Run Functions
- Used to be called Cloud Functions
- Services are triggered by some event, e.g. 
	- File uploaded to bucket
	- pub/sub message received
- Like App Engine, basically creates a container and runs it

Cloud Scheduler
- Can also run cloud function on schedule
- Although weirdly, it looks like you can also trigger by hitting a url

Cloud Storage
- Generally use buckets to store stuff like files, e.g.
	- Questionnaire package for DQS
	- RAT ROS receipt images
	- Also dev stuff like installers
		- Not ideal; may change in future

Cloud SQL
- SQL instance
- Has private IP, requires auth so data is not exposed to internet
	- Blaise installation is given details of Cloud SQL instance
- Shows metrics for monitoring
- Instances have password policy for complex pwds
- Blaise has its own account
- CloudSQL Studio to query
	- Needs account
	- Blaise captures some info as datastreams - not human readable
- Alternative to query data
	- Connect to blaise-gusty-mgmt
		- Use Heidi
		- Less secure
	- Open tunnel to instance as localhost
		- Use mySQL

Datastore

		- Benefit from flexible noSQL
